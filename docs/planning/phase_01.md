# 第一阶段：可运行框架原型

## 已实现

- Godot 4.7.2 .NET / C# / net10.0 工程，1920×1080 设计空间、16:9 等比缩放。
- `Core/Data`：CSV 标准引号解析和导出、数值与外键校验、首杀妖核投放约束、天赋环路检查。
- `Core/State`：版本 1 快照、永久首杀账本、原子替换与备份恢复。
- `Features/Battle`：纯 C# 固定步长会话，移动、刷怪、技能、敌人行为、伤害、复活、传送。
- `Features/Talent`、`SwordRealm`、`Forging`、`SwordIntent`、`SwordSpirit`：五大系统初版操作，统一扣费和保存。
- `UI`：战斗表现、共享主题、五页交互、资源/气血/进度、存档状态、关卡选择、GM 调试与设置面板。
- 全部 12 张用户指定表，加波次、刷怪点、掉落、连线、参悟与设置，共 18 张 CSV。
- 100 关、15 剑诀、5 天赋节点、3 武器、60 剑意强化、3 剑灵、3 类增强的样例内容。
- 像素格占位美术与独立资源路径映射。
- 程序化生成的 8bit 占位音频（1 首循环 BGM + 14 个音效）与独立资源路径映射，生成器见 `tools/SoundGen/`。

**召唤/跟随单位的站位**由表现层分配位次（`BattleView.FollowerSlot`），左右交替、逐层向外抬高，天然兼容以后更多的召唤物与随从。Core 每步把召唤物的 `X` 钉在玩家身后，那只是逻辑锚点，站位与伤害无关——不要改回"让 Core 算错开位置"。位次在单位到期时只释放自己那一格，剩余单位不会整体挪位。

表现层只读模拟状态：命中由血条差分还原，状态图标直接读取 `EnemyState` 公开字段，未向 `Core/` 添加任何仅供显示的状态。`CombatEffect` 新增 `Skill`（来源剑诀）与 `MaxLife`（初始时长）两个表现用只读字段，均为瞬态、不入存档。

数值仍为草案初值，本轮目的只是让差异可见，**效果差异需人工审核一轮后再定稿**。

### 技能预览模式

底栏"技能预览"按钮（`UI/SkillPreview.cs`）进入逐个剑诀的对照模式：

- 用**独立会话**播放，不写存档、不参与玩家进度；预览期间主线挂机暂停，避免看技能时后台仍推进关卡。
- 场上是固定靶：不移动、不反击、打不死，15 个剑诀面对完全相同的对照条件。
- 每 1.8 秒重置所选剑诀冷却，12 秒冷却的大招也能快速反复观察。
- 切换剑诀时清空飞行效果、玩家增益与飘字，避免两招混在同一画面里失去对照意义。
- 页面显示该剑诀的境界/类型/冷却/射程/威力/次级效果与说明，`◀ 上一个 / 下一个 ▶` 或直接点按钮切换。

`--capture` 会顺带为 15 个剑诀各出一张 `preview-skillNN.png`，供离线逐张核对。

### 设置面板

顶栏右侧「设置」按钮打开（`UI/SettingsPanel.cs`），分三节：

- **画面**：分辨率下拉（1280×720 / 1600×900 / 1920×1080 / 2560×1440 / 3840×2160）与「全屏显示」开关，改动即时生效，落到真实窗口而不只是写进配置文件。
  - **全屏时分辨率下拉会被禁用并把标签改成「分辨率（全屏时无效）」**：全屏走的是桌面分辨率，此时改分辨率不会有任何可见变化，不说明的话会让人以为设置没生效。
  - **玩家拖动窗口边缘改出来的尺寸会被采纳**（`SizeChanged` → 设置），面板里补一条「（当前）」项如实显示；否则面板说的分辨率和真实窗口对不上，下次启动还会弹回旧预设。
  - **从最大化/全屏退回窗口模式时，设尺寸要推迟一帧**：Windows 会异步把窗口还原成进入之前的尺寸，同帧设的尺寸会被那次还原盖掉，表现为"先最大化、再改分辨率没反应"（`_pendingSize`）。
  - **`RefreshSettings` 回填勾选框必须用 `SetPressedNoSignal`**：`ButtonPressed` 的 setter 会发出 `Toggled`，于是"打开设置面板"会反过来触发 `ApplyDisplay` 把窗口重设一遍并落盘——玩家手动拖出来的尺寸会被悄悄弹回旧预设，配置说全屏时开面板还会直接把窗口顶成全屏。
- **音频**：音乐、音效音量滑杆（0～100），分别控制 `Music` / `SFX` 两条音频总线，总线不存在时按需创建。
- **重置**：**二次确认**——第一次点击只进入待确认状态并把按钮文字改为「确认重置？再点一次」，5 秒内再点一次才真正清档，超时或关闭面板自动撤销。清档会重建 `GameSession`、删除主存档与备份、重置关卡解锁与首杀账本；画面与音量偏好**不受影响**。

设置存放在独立的 `user://settings.json`（`Core/State/AppSettings.cs`），与玩家存档分开：设置不是进度，文件缺失或损坏时回落到默认值继续启动，而不是像存档那样拒绝加载；读入时夹取到合法范围，避免手改配置让窗口变成 0×0。

重置前若处于技能预览模式会先退出预览，否则画面读的是预览会话、存档写的是主线会话，两者对不上。

## 音频（占位素材）

15 个 16bit PCM 单声道 22050Hz WAV，全部由 `tools/SoundGen/` 程序化合成，产物与生成器都入库：

```bash
dotnet run --project tools/SoundGen -- idle-sword/Assets/Audio   # 生成
dotnet run --project tools/SoundGen -- idle-sword/Assets/Audio --verify   # 只回读校验
godot --headless --path idle-sword --import   # 必须跑，否则 GD.Load 拿到 null
```

- **BGM**：`bgm_battle` —— 150 BPM / 16 拍 / 6.4 秒循环曲，五声音阶（宫商角徵羽）主旋律 + 三角波贝斯 + 噪声打击。
- **技能释放**：`sfx_cast_{projectile,target,ground,buff,summon}`，**按剑诀 kind 分 5 种**，直接由 `SwordSkill.csv` 的 `kind` 字段驱动，新增或改动剑诀自动归类，不维护额外映射表。
- **战斗**：`sfx_hit`（普通命中）、`sfx_hit_heavy`（重击）、`sfx_kill`（击杀）。
- **界面与养成**：`sfx_click`、`sfx_panel`、`sfx_buy`、`sfx_deny`、`sfx_reward`（首杀妖核）、`sfx_breakthrough`（突破境界）。

触发点全部在表现层，音频不进入 `Core/`：

| 音效 | 触发方式 |
| --- | --- |
| 命中 / 击杀 | `BattleView` 的血量差分：命中看掉血，击杀看敌人"从列表消失"（死亡的敌人已在同一次 Step 里被移除，差分看不到 `Hp<=0`） |
| 技能释放 | **技能冷却 0 → 正 的跳变**，逐 Step 观测 |
| 首杀奖励 | `FirstKills` 账本计数增加 |
| 界面 / 养成 | `UiKit.Button` 的唯一创建入口、`Act` 的成功/失败分支、设置面板开合 |

几个容易踩的点，改动时别退回去：

- 释放音**不能**用"比较 `Session.Effects` 的引用集合"来检测：3 个 buff 类剑诀走 `CastBuff`，根本不产生 `CombatEffect`，差集法会永久漏掉护心剑罡 / 归元护法 / 万剑归心。冷却边沿对五种 kind 一律成立。
- 换场守卫用 **`BattleState` 对象身份**，不能用关卡 id：死亡回到起点和整关循环都回到**同一个关卡 id**，id 守卫挡不住，会把旧敌人全当成击杀、刷一波死亡音。
- BGM 循环必须设满 `LoopMode` / `LoopBegin` / `LoopEnd` 三项。WAV 导入器默认 `loop_mode=0`（不从文件探测），而运行时 `loop_end` 默认是 `0`——那是空循环区间，不是"到文件末尾"；只设 `LoopMode` 会看着对、实际不循环。
- BGM **不按音量判断是否播放**，音量交给总线 dB。否则启动时音量为 0 就永远不播，玩家把滑杆拉上来也不响。
- WAV 导入统一用 `compress/mode=0`（16bit PCM）。该枚举在 4.7 里与旧文档不一致，实测：`0`=PCM 16bit、`1`=IMA-ADPCM(4bit)、`2`=QOA；Godot 对新 WAV 的默认值是有损压缩，会削掉方波的硬边。
- 音频是可选素材：`audio.json` 缺失或单个文件加载失败时写进 `AudioLoadError` 并继续启动，**不抛异常**（`_Ready` 里的异常会被 Godot 吞掉，变成"没声音但自检照样通过"）。
- **重复抑制**（`SfxPolicies`）是音效层的通用闸门，不是给灼烧打的补丁：最短重触发间隔（命中 0.09s / 重击 0.14s / 击杀 0.10s，其余 0.03s）+ 音高微随机。持续伤害逐跳结算、范围技能同帧打中多个、密集小怪同时挨打，都会让同一个音在一秒内触发几十次。抑制时钟用**模拟时钟**（`Active.Elapsed`）而不是真实时间：放置游戏的模拟时间会与真实时间脱节（追帧、预览加速、一次长帧合并多个 Step），跟着模拟事件走才不会把一秒内的事件挤在一瞬间放出来，也才可被自检确定性验证。
- 灼烧判据（`BattleView.IsBurnTick`）的阈值必须按**本帧模拟了多少秒**算，不能用 `_Process` 的真实帧间隔：跳伤按固定步长成块结算（每步 `DotDps * fixed_step`），而真实帧间隔通常**小于**固定步长，阈值会低于单步跳伤，判据永不成立，每一步都播一次命中音（约 20 次/秒）。这一条曾经写反过，注释里记的是"一帧合并多个 Step 会让累积伤害超过阈值"，方向正好相反。

## 本阶段采用的暂定规则

这些规则用于验证系统接口，后续技能、天赋和锻造设计可以替换：

- 每格使用一个默认刷怪点，位置从 `spawn_point.csv` 首行读取；进入格时首波立即刷新。
- 角色独立停步距离 640，普攻射程 1000；各技能独立射程。角色初始已习得第一技能。
- 剑诀每级基础效果加成 15%，无施法资源；Buff 示例提供伤害倍率与 5% 气血恢复。
- 天赋有一个已加点前置即可开放；加点不需要前置满级，暂不提供洗点。
- 武器直接打造并装备，替换时不保留旧武器，强化重置；每级武器攻击 +15%，洗练攻击品质 90%～130%。多武器实例、背包、品质词条池留待铸剑设计。
- 4 页剑意目前都是对应技能效果加成，每级 +8%；Buff 技能强化的是倍率，其他技能强化伤害。
- 参悟初期每次点击 1 份，各类最多积存 200；自动参悟每类独立计时，满仓暂停计时，收取后继续。
- 剑灵抽取消耗灵钱，权重 50/30/20；重复返还 40 灵钱，无保底；首次获得自动出战（最多 3）。
- 剑灵 3 类增强暂时都提高技能伤害，购买即装备，暂不提供卸下与背包。
- 复活等待 2 秒；BOSS 格在本格安全位置满血复活，保留敌人和裂隙血量；等待期间冻结战斗与刷怪，但在线参悟继续。
- 正常退出保留战斗快照；重新进入不重演弹丸/持续区域/召唤物，不结算退出期间时间。
- 100 关样例 HP 按 1.13 的幂增长，ATK 按 1.09 的幂增长；不是最终平衡曲线。

## 技术取舍与后续工作

- 选择 Compatibility 渲染器支持简单 2D，替换了空工程原有的 Forward Plus / D3D12 设置。
- 使用有限 double 数值与集中格式化，100 关样例足够；真正的超大数值类型与完整溢出处理留给长尾数值阶段。
- 普通数据 CSV 的 `.import` 使用 `keep`，避免 Godot 当作本地化表生成 Translation；导出显式包含原始 CSV。
- 配置为启动时加载，修改后重启；有标准 CSV 写入/导出工具，没有游戏内配置编辑器。
- 音频是**程序化生成的 8bit 占位素材**，不是最终音频设计，也不是外部素材。生成器 `tools/SoundGen/` 与产物 WAV 一并入库，改一处参数重跑即可迭代。音乐与音效音量滑杆依然通过 `Music` / `SFX` 两条总线的 dB 生效，接入真实音频后无需改动滑杆代码。
- 设置面板为按需构建的单层覆盖层（半透明背板），不使用 Godot 弹窗节点，保持与主界面同一套 1920×1080 设计坐标。
- 设置与进度分文件存放，因此「重置进度」不会连带清掉画面与音量偏好。
- 场上怪物不因数量上限被删除；仅表现层限制最多绘制 80 个可见怪物。超大规模压力测试、空间查询优化与对象池后续根据实测追加。
- 目前是同一 GameSession 的分文件功能实现，避免功能互相操作 UI。复杂系统细化时可再拆独立服务。
- Windows EXE 导出预设已提供，发行导出与打包尚未验证。
- 最小化不主动暂停，也不使用焦点暂停；系统睡眠和长时间操作系统挂起不作为离线收益补算机制，需后续专项挂机压力测试。

## 验证记录

- .NET 构建：0 警告、0 错误。
- 逻辑检查覆盖 CSV 读写、非法数据、波次叠加、移动补怪/停刷、两类死亡、裂隙门槛、首杀去重、100 关有限投放、整关循环、技能、参悟、养成和存档。
- 持续模拟验证基础角色可以到达 BOSS 并获得首杀妖核。
- Godot 无窗口启动与 UI 信号测试通过；带渲染截图检查全部五大系统页面及剑意子页面。
- 设置面板走真实信号自检：改音量后校验 `AppSettings` 与 `Music` 总线 dB 同时生效、写盘后重新读回一致；重置必须先在第一次点击时保持进度不变、第二次点击才恢复初始状态（灵钱回到初始值、妖核归零、关卡解锁回到 1、首杀账本清空、剑诀回到 1 个），且面板自动关闭。
- 预览模式下重置有专门断言：重置后必须已退出预览且战斗视图重新绑定主线会话。该断言在移除修复后确认会失败，不是空断言。
- 窗口分辨率以带渲染运行核对：`DISPLAY (1280, 720) mode=Windowed`，确认设置真的落到真实窗口，而非仅写入配置文件。无窗口自检下 `DisplayServer` 为 dummy，按设计跳过该步。
- 显示设置的四条断言走**真实控件信号**（不是直接改 `_settings` 再调 `ApplyDisplay`），只有 `--capture` 带显示时才跑：
  1. 分辨率下拉发 `ItemSelected` 后真实窗口跟着变；全屏勾选框发 `Toggled` 后显示模式真的切换，退回时分辨率不丢。
  2. **先最大化再改分辨率也要生效**——这条曾实际失败过，正是推迟一帧应用那个修复的由来。
  3. 拖拽出来的尺寸要被设置采纳。
  4. **开面板不得自己改显示模式或改窗口尺寸**：故意让配置说"全屏"而窗口停在窗口模式，面板只该如实勾选；同时确认分辨率下拉在该状态下被禁用。
  - 断言轮询若干帧而不是读一次：改窗口尺寸/显示模式要经操作系统一圈，读回值会落后一两帧，只看一帧会偶发失败。
  - 非空验证：把 `SetPressedNoSignal` 改回 `ButtonPressed` → 退出码 1（`Opening settings applied the display mode by itself`）；注释掉 `SizeChanged` 连接 → 退出码 1（`Hand resize not captured: 1280x720`）；去掉推迟一帧 → 退出码 1（`Resolution did not apply from a maximized window`）。
- 音频自检覆盖到每个素材的触发路径：`AudioLoadError` 为空、BGM 的 `LoopMode/LoopBegin/LoopEnd` 三项正确（证明循环真的生效）、5 种 `kind` 的释放音各至少播过一次（**尤其验证 buff 类**，那是差集法会漏掉的一类）、命中与重击两个分支、击杀、首杀奖励、突破、点击与面板音。自检结束打印各类播放计数。
- 「普通命中」与「重击」两个分支在 1 级时不会自然分开（角色几乎一击秒杀，伤害占比总是越过重击阈值），自检为此专门放一个高血量靶子把普通命中分支跑到。
- `AudioLoadError` 断言非空验证：故意把 `audio.json` 指向不存在的文件，确认自检真的以退出码 1 失败，并同时给出启动提示。
- 灼烧跳伤不出声有一条端到端断言，跑在**独立会话**里（主线会话仍在挂机走路、可能死亡重生或补怪，任何一次额外命中都会污染"场上只有跳伤"这个前提）。该会话把刷怪点全部标记为已越过——**清空 `Battle.Spawns` 没用**，`ActivateCell` 会在下一步把本格重建并补怪，怪正好落在角色身边挨打。
- 这条断言的主判据是 `BattleView.BurnTicks`（判定为跳伤的次数），不是"没听到命中音"：抑制机制用的是主线模拟钟，而自检每帧只推进 7ms、固定步长是 50ms，那口钟几乎不走，误判出来的命中音会被整批丢掉、计数不变——"没出声"是**能被抑制机制掩盖**的断言。把调用点改回真实帧间隔后，该断言确认以退出码 1 失败（`Burn ticks were not classified as burn`），不是空断言。
- 召唤物站位断言：往会话里放 3 个召唤物，要求位次互不相同、屏幕坐标互不相同、且不全部落在玩家同侧。把 `AssignCompanionSlots` 改成恒定位次 0 后确认以退出码 1 失败（`Summons shared a slot: 0,0,0`）。
- `SFX PLAYS` 行会打印被抑制的次数（`throttled=`），无窗口自检为 11、带渲染自检为 23，说明闸门在真实运行路径上确实生效。
- **已知的退出噪声（非真实泄漏）**：Godot 的退出泄漏检查跑在 .NET GC 之前，会偶发报 "ObjectDB instances were leaked / resources still in use"。同一份二进制连续运行会出现「0 / 13 / 33」的浮动，加 `--verbose` 的那次为 0，故判定为 GC 时机产物而非泄漏。`Main._ExitTree` 已主动释放播放器持有的流引用以减少残留。
